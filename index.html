TURTLE GP Documentation

TURTLE GP is a modern, self-hosted game server management panel. A React + Vite dashboard talks to an Express + TypeScript API, while a lightweight daemon ("Wings") runs on each of your game machines and streams logs, stats, and file access back over a secure WebSocket connection.

PanelWeb UI + REST API
→
WingsDaemon on each node
→
Game serversJava / SteamCMD

Highlights

  • Multi-server and multi-node management from a single dashboard.
  • Bundled Java runtimes (8, 11, 17, 21, 25, 26) with automatic download.
  • SteamCMD integration to install and update Steam games.
  • Live console over WebSocket with command input.
  • SQLite (zero-config) or MySQL/MariaDB storage.
  • File manager, SFTP, backups, cron schedules, subusers, and more.

Installation (Windows)

Double-click start.bat in the project root. The script runs five self-checks:

  1. Java — checks PATH, then tools\java, and downloads Eclipse Temurin JDK 21 if missing.
  2. SteamCMD — downloads steamcmd.exe if not found and runs its initial setup.
  3. Node.js + npm — verifies both are installed.
  4. Ports — kills any stale process on ports 3001 and 5173.
  5. Project files — verifies server/src/index.ts and panel/src/App.tsx exist.

If dependencies are missing it runs npm install, writes a default server\.env, then starts both processes with concurrently:

Backend:  http://localhost:3001
Frontend: http://localhost:5173

Manual setup

npm install                  # install root dev tools (concurrently)
cd server && npm install       # backend dependencies
cd ../panel && npm install    # frontend dependencies
cd ..
npm run dev                  # runs server (3001) + panel (5173)

Linux

The server, panel, and Wings daemon all run on Linux. Use daemon/deploy.sh and the bundled wings.service systemd unit for the daemon.

Port conflict? If a stray PORT environment variable is set in your shell, the backend can bind the wrong port. start.bat forces PORT=3001 and frees ports before launching.

Database

SQLite (default)

With DB_TYPE=sqlite no external services are needed. Data is stored in data/turtle-gp.db. All 19 tables are created automatically on first start.

MySQL / MariaDB

You can switch to MySQL during the install wizard. The wizard:

  1. Writes the connection details to server/.env.
  2. Reconnects the backend to MySQL.
  3. Drops any existing TURTLE GP tables (clean install).
  4. Runs migrations to create the full schema, then creates the admin account.

A POST /api/install/validate-db endpoint lets you test the connection before committing. MySQL-specific SQL is converted automatically (e.g. datetime('now') → NOW(), INSERT OR REPLACE → REPLACE INTO, reserved words are backtick-quoted).

Troubleshooting: if the server closes immediately when starting, MySQL is usually the cause — either it isn't running, or DB_TYPE points to MySQL while no server is available. Switch to DB_TYPE=sqlite to run without a database server.

First login

  1. Open http://localhost:5173 (or http://localhost:3001/install if redirected).
  2. The install wizard asks for an admin username, password (min. 10 characters), panel name, and database choice.
  3. For MySQL, fill host / port / name / user / password and optionally test the connection first.
  4. After setup, sign in and you land on the dashboard.

From the dashboard you can create servers, register nodes, and manage users via Admin pages.

Servers

Servers are the core unit of the panel. Each server has a game, an owner, resource limits (RAM, CPU, storage), ports, and a startup command.

  • Statuses — starting, running, stopping, stopped, installing.
  • Limits — per-server RAM (ramLimit), CPU (cpuLimit) and storage (storageLimit).
  • Java version — pick any bundled runtime per server (8, 11, 17, 21, 25, 26).
  • Ports — internal/external port allocations with protocol per label.
  • Auto-restart — keep the process alive with the watchdog on the daemon.
  • Player query — live player counts via GameDig for supported games.

File manager

The web file manager lets you browse, upload, download, rename, delete, and edit server files. Bulk operations can be done over SFTP — each node exposes its own SFTP server (default port 2022).

Backups

Create on-demand or scheduled backups of any server. Backups are archived, stored under data/backups, and can be downloaded or restored at any time.

Schedules

Scheduled tasks run on cron expressions (default 0 4 * * *) and can start, stop, or restart servers automatically. The scheduler starts with the backend and supports per-server tasks.

Subusers

Grant other accounts access to a server with granular permissions: console, files, start, stop, restart, and settings. A single user can be a subuser on many servers.

Minecraft plugins

Search and install plugins directly from the panel. Supported sources include Modrinth, Hangar, and Spigot. Servers support Paper, Purpur, Spigot, Folia, Velocity, Waterfall, BungeeCord, Vanilla, Forge, NeoForge, Fabric, Quilt, Mohist, and SpongeForge variants.

Tickets & support

Two systems are built in: server tickets (users request a server with limits and a reason) and a support desk (subject, priority, internal notes, attachments, and responses). Both have admin views and are logged in the audit log.

Game databases

Manage MySQL hosts and create per-server databases with dedicated credentials. Each server can have one or more server databases on any configured host.

Subdomains

Create DNS subdomains pointing at server targets. With a Cloudflare API token and zone configured, records are created automatically and can be proxied.

Wings daemon

daemon/ is the Wings agent (v1.6.0). It runs on each machine that hosts game servers and communicates with the panel over WebSocket using a node token.

Windows

cd daemon
start.bat   # runs setup wizard on first start, then launches

Linux

cd daemon
./deploy.sh
# or install as a service:
sudo cp wings.service /etc/systemd/system/
sudo systemctl enable --now wings

Responsibilities:

  • Process manager — starts/stops servers, watchdog restarts.
  • SFTP server — built-in file access (default port 2022).
  • Stats — reports CPU, RAM, and disk usage to the panel.
  • Health server — node health checks and heartbeats.

Nodes & locations

A node represents a machine running Wings. Nodes report RAM, disk, CPU, version, and uptime (heartbeat). The first node is marked isLocal by default. Servers are assigned to a node, optionally grouped by location.

Troubleshooting & FAQ

Server window closes immediately on start.bat

Usually MySQL. Either start MySQL/MariaDB, or set DB_TYPE=sqlite in server/.env (keep the DB_PASSWORD= line). Also make sure no stray PORT env variable conflicts.

Port already in use (EADDRINUSE)

start.bat kills stale processes on ports 3001 and 5173 automatically. Manually: netstat -ano | findstr :3001 then taskkill /F /PID <pid>.

How do I reset / reinstall?

Delete data/turtle-gp.db (SQLite) or drop the MySQL database, then restart. The server will show the install wizard again.

Where are server files stored?

Under servers/ for the local node. The data directory defaults to data/ (configurable via DATA_DIR / SERVERS_DIR).

Can I add more machines?

Yes. Install the Wings daemon on another machine, register it as a node in the panel, and assign servers to it.

Is registration open by default?

Yes, unless ALLOW_REGISTRATION=false in server/.env or registration is disabled in panel settings.
